모든 개념에 적용할 학습법

1단계
기초적으로 알아야 하는 개념

코드를 읽기 위한 언어를 준비합니다.

개념 / 항목쉽게 이해하기 · 실제 적용
파일·경로폴더는 서랍, 파일은 그 안의 종이입니다. 상대 경로는 현재 파일을 기준으로 찾는 주소입니다.
적용: index.html의 css/style.css 연결
확인: CSS 파일명을 바꾸면 꾸밈이 사라지는 이유를 설명한다.
HTML 태그·속성태그는 내용의 종류, 속성은 추가 설명입니다. h1은 큰 제목, href는 이동 주소입니다.
적용: h1, a href="#projects"
확인: href와 대상 id가 같아야 이동함을 확인한다.
CSS 선택자·박스 모델선택자는 꾸밀 대상, padding은 안쪽 여백, margin은 바깥 여백입니다.
적용: .button, .section, box-sizing
확인: 버튼 padding을 키워 글자는 같아도 버튼이 커짐을 본다.
변수·값·조건변수는 이름 붙인 값입니다. const는 재할당 금지, let은 재할당 가능입니다.
적용: state 객체, requestVersion 변수
확인: const 객체의 속성은 바뀔 수 있음을 구분한다.
함수·객체·배열함수는 재사용할 일, 객체는 한 대상의 정보, 배열은 순서 있는 목록입니다.
적용: samples 배열의 프로젝트 객체, renderTheme 함수
확인: name은 카드 한 개의 속성이고 samples는 목록임을 말한다.

2단계
필수적으로 알아야 하는 개념

과제의 주요 기능을 스스로 따라가 봅니다.

개념 / 항목쉽게 이해하기 · 실제 적용
시맨틱 HTML의미 있는 영역 이름입니다. nav는 길 안내, main은 주요 내용입니다.
적용: header/nav/main/section/article/footer
확인: article과 section을 사용한 기준을 말한다.
Flexbox·Grid·반응형Flex는 한 방향 정렬, Grid는 행과 열 배치에 편합니다. 반응형은 화면 너비에 맞춘 조절입니다.
적용: 메뉴 Flex, 프로젝트 Grid, 768/1024px
확인: 모바일 한 열과 데스크톱 여러 열의 차이를 설명한다.
DOM·이벤트·렌더링DOM은 브라우저가 만든 요소 구조, 이벤트는 발생한 행동, 렌더링은 상태를 화면에 반영하는 과정입니다.
적용: querySelector, addEventListener, renderTheme
확인: 클릭 → theme 변경 → data-theme 반영을 찾는다.
ES6+·배열 메서드화살표 함수는 함수 문법, 구조분해는 속성 꺼내기입니다. map은 변환, filter는 선별, forEach는 순회입니다.
적용: renderProjects의 filter → map → join
확인: CSS 필터가 원본 목록을 지우지 않는 이유를 말한다.
비동기·API·JSONAPI는 데이터 요청 규칙, JSON은 데이터를 담는 형식입니다. await는 비동기 작업의 결과를 기다립니다.
적용: loadProjects의 fetch와 response.json()
확인: 기다리는 동안에도 메뉴 클릭이 가능한 이유를 말한다.
폼·저장·상태입력 검사 결과와 테마 선택도 상태입니다. localStorage는 브라우저에 값을 보관합니다.
적용: validate, preventDefault, localStorage
확인: 입력 오류를 고치면 에러가 사라지고 테마는 새로고침 후 유지됨을 확인한다.

문제가 생겼을 때 고치고, 사용자를 배려합니다.

개념 / 항목쉽게 이해하기 · 실제 적용
HTTP 오류·예외fetch는 404/403 응답만으로 자동 실패하지 않습니다. response.ok를 확인해야 합니다.
적용: loadProjects의 !response.ok와 try/catch
확인: 존재하지 않는 계정과 요청 제한도 오류 화면으로 안내한다.
접근성키보드나 화면 읽기 도구로도 사용할 수 있어야 합니다. label, alt, 초점, aria가 돕습니다.
적용: label for-id, aria-expanded, aria-live, :focus-visible
확인: Tab으로 버튼에 접근하고 오류 난 첫 입력으로 초점이 이동하는지 본다.
외부 데이터·XSS외부 문자열을 HTML로 그대로 넣으면 악성 코드로 해석될 수 있습니다. 텍스트로 처리하거나 이스케이프합니다.
적용: escapeHTML, safeRepoURL, textContent
확인: 프로젝트 설명의 < 문자가 태그로 실행되지 않는지 확인한다.
디버깅·CSS 우선순위콘솔은 실행 오류, Network는 요청 결과를 보여줍니다. CSS는 더 구체적인 규칙 등이 우선합니다.
적용: 테마 선택자와 공통 변수; 개발자 도구
확인: 색이 안 바뀌면 적용된 스타일과 선택자를 먼저 확인한다.
검증과 전송의 차이브라우저 검증은 UX 보조입니다. 실제 전송 서비스는 서버에서도 검증해야 합니다.
적용: 폼 성공 안내에 실제 미전송 명시
확인: 성공 문구가 곧 이메일 발송 증거는 아님을 설명한다.
Git·GitHub·배포Git은 변경 기록 도구, GitHub는 저장·협업 서비스, Pages는 웹 게시 기능입니다.
적용: 로컬 파일과 공개 사이트 URL
확인: 내 컴퓨터 경로를 다른 사람에게 줘도 열 수 없음을 이해한다.

API 오류와 인증 없는 기본 요청 제한(시간당 60회)은 GitHub 공식 문서 참고. 반복 새로고침 대신 학습 실험실로 상태를 재현할 수 있습니다.

요청 경쟁·취소먼저 시작한 요청이 나중에 도착하면 최신 화면을 덮을 수 있습니다. 오래된 요청을 무시하거나 취소합니다.
적용: requestVersion, AbortController, 12초 타임아웃
확인: API 대기 중 예시로 바꿔도 예시가 유지되는 원리를 이해한다.
관찰자·움직임 배려Intersection Observer는 요소가 보이는 정도를 관찰합니다. reduced-motion은 움직임을 줄이라는 사용자 설정입니다.
적용: threshold:0.2, prefers-reduced-motion
확인: 관찰 대상의 약 20%가 보이면 나타나는 효과를 적용한다.
점진적 향상기본 내용을 먼저 제공하고 지원되는 기능을 더합니다. JS가 실패해도 소개 내용은 남게 설계합니다.
적용: Observer 지원 검사, HTML의 정적 소개
확인: JS가 없으면 기본 소개는 남지만 카드·검증은 작동하지 않음을 구분한다.
디자인 토큰색·간격·반경에 이름을 붙여 여러 곳에서 공유하는 설계 방식입니다.
적용: --bg, --accent, --radius
확인: 테마 하나를 바꾸면 여러 요소가 함께 바뀌는 이유를 말한다.
페이지네이션·캐시많은 데이터를 나눠 받거나 이전 응답을 재사용하는 방식입니다.
적용: 현재 per_page=100; 추가 페이지·캐시는 미구현
확인: 저장소가 100개보다 많을 때 모든 목록을 받으려면 확장이 필요함을 안다.

자주 섞이는 개념

개념 / 항목쉽게 이해하기 · 실제 적용
HTML ≠ DOMHTML은 작성한 문서이고 DOM은 브라우저가 문서를 읽어 만든 조작 가능한 구조입니다.
class ≠ idclass는 여러 요소를 묶는 이름, id는 페이지에서 한 요소를 식별하는 이름입니다.
map ≠ forEachmap은 반환값들을 새 배열로 만들고, forEach는 순회 작업을 합니다. forEach 결과로 카드 배열을 만들 수는 없습니다.
로컬 저장 ≠ 서버 저장localStorage는 해당 브라우저·출처에 저장합니다. 다른 기기로 자동 동기화되지 않고 삭제되거나 저장이 제한될 수 있습니다.
await ≠ 전체 화면 정지비동기 함수의 다음 처리를 기다립니다. 네트워크 대기 중 브라우저의 다른 상호작용까지 멈추는 것은 아닙니다.
