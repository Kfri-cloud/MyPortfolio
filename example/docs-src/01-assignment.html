무엇을 만드는 과제인가?

HTML은 내용, CSS는 모습, JavaScript는 행동을 맡습니다.

개념 / 항목쉽게 이해하기 · 실제 적용
HTML · 뼈대제목, 자기소개, 기술 목록, 프로젝트, 문의 폼에 의미와 순서를 부여합니다. 예: <h1>은 가장 중요한 제목입니다.
CSS · 꾸미기글자 색, 여백, 카드 배치, 화면 크기별 모양을 결정합니다. 예: 넓은 화면의 카드 여러 열이 좁은 화면에서는 한 열이 됩니다.
JavaScript · 동작클릭과 입력을 감지하고 화면을 바꿉니다. 예: 다크 모드 버튼을 누르면 색상 묶음을 교체합니다.
GitHub API · 자료 요청외부 서비스에 공개 저장소 목록을 요청해 카드로 바꿉니다. 인터넷이 느리거나 실패해도 상황을 알려야 합니다.
GitHub Pages · 공개 주소완성한 파일을 인터넷에서 열 수 있도록 게시합니다. 내 컴퓨터에서만 열리는 파일과 공개 URL은 다릅니다.

겉모습보다 중요한 한 줄

사용자 이벤트 → 상태 변경 → DOM 업데이트 → 화면 변화
예: 방의 전등 스위치

스위치를 누르는 행동은 이벤트, 불이 켜졌는지는 상태, 방이 밝아지는 것은 화면 변화입니다. 웹에서는 버튼 클릭, theme 값, CSS 적용이 각각 그 역할을 합니다.

과제의 학습 조건

원문은 80시간 학습 과제입니다. React, Vue, jQuery, Bootstrap, Tailwind 같은 외부 라이브러리 없이 순수 HTML/CSS/JavaScript로 구현합니다. 이번 웹도 실행용 외부 라이브러리를 사용하지 않습니다.

원문 근거: 1~2쪽(목표·결과물), 7쪽(환경·제약). PDF 및 캡처 제작 도구는 웹 실행 코드와 별도입니다. 원문의 “브라우저가 이해하는 유일한 언어” 표현은 입문용 단순화이며, 여기서는 웹 프론트엔드의 핵심 세 기술로 이해합니다.

필수 개념 목차와 학습 순서

코드를 모두 외우기보다, 각 단계에서 작은 변경을 직접 하고 결과를 설명하는 것이 목표입니다.

개념 / 항목쉽게 이해하기 · 실제 적용
① 파일과 실행폴더, 확장자, 상대 경로, 브라우저, 편집기, Live Server. → index.html을 열고 소개 문장 하나를 바꾸기.
② HTML의 의미태그, 속성, 제목 단계, 시맨틱 구조, 앵커, alt, label. → 메뉴 링크가 가리키는 section의 id 찾기.
③ CSS와 반응형선택자, 상속·우선순위, 박스 모델, 변수, Flex/Grid, 미디어 쿼리. → 카드 간격과 화면 너비를 바꿔보기.
④ JavaScript 기초const/let, 문자열, 객체, 배열, 함수, 조건, 템플릿, 구조분해. → 프로젝트 설명을 수정하고 카드 확인하기.
⑤ DOM·이벤트·상태요소 선택, 이벤트 리스너, classList, 상태와 렌더링, 기본 동작 취소. → 테마 버튼의 클릭 흐름을 말로 설명하기.
⑥ 비동기와 예외JSON, Promise의 기초, fetch, async/await, HTTP 상태, try/catch. → 로딩/성공/오류/빈 상태를 각각 재현하기.
⑦ 품질과 제출폼 검증, 저장소, 접근성, 외부 데이터 처리, 콘솔·Network, Git/GitHub/Pages 구분. → 모바일 검사 후 본인 정보로 교체하고 배포하기.

80시간을 나누는 예시 계획

환경과 과제 분석 6h → HTML 10h → CSS/반응형 16h → JS/DOM 18h → API와 폼 16h → 검증/배포/회고 14h. 시간 배분은 이 안내서의 제안이며 원문이 지정한 세부 시간표는 아닙니다.

예시 실행과 제출 준비

지금 예시를 보는 방법

  1. portfolio/index.html을 브라우저에서 엽니다. 기본 예시 카드와 모든 로컬 인터랙션을 사용할 수 있습니다.
  2. 과제와 같은 개발 흐름은 VS Code에서 portfolio 폴더를 열고 Live Server로 index.html을 실행하는 것입니다. 저장 후 화면이 갱신되는지 확인합니다.
  3. Projects의 데이터 선택을 GitHub 실제 연결로 바꾸면 인터넷으로 octocat의 공개 저장소를 요청합니다.
  4. 학습 실험실에서 로딩·에러·빈 상태를 확인하고, 문의 폼에 빈 값이나 잘못된 이메일을 입력해 봅니다.

실제 과제로 제출하려면

  1. 가상 이름·소개·일러스트를 본인 내용으로 교체합니다.
  2. js/main.js의 GITHUB_USERNAME과 HTML의 안내 문구·GitHub 링크를 본인 계정에 맞춥니다. 제출본은 실제 API 연결을 기본값으로 바꾸는 것이 좋습니다.
  3. 별도 GitHub 저장소의 최상위에 portfolio 폴더 안의 파일을 올립니다. index.html이 저장소 루트에 있게 합니다.
  4. 저장소 Settings → Pages에서 게시 원본을 해당 브랜치와 /(root)로 지정합니다. 생성된 URL을 README에 기입합니다.
  5. 공개 URL에서 반응형, API, 테마, 폼을 다시 검사하고 데스크톱·모바일·다크 화면을 함께 제출합니다.
현재 완료 범위

웹 예시, 학습 PDF 3종, 실제 화면 캡처, 기능 검증이 포함됩니다. 본인 계정 적용·개인 환경 설정·공개 배포는 완료되지 않았습니다. 문의 폼은 입력 검증만 하며 메시지를 전송하지 않습니다.
